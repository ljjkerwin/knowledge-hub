## 初版核心指标

| 指标                                  | 指标意义                                                                          | 计算方式                                                      | 评估方式                                                                 |
| ------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 请求完成率 `request_success_rate`     | 判断 Agent 是否稳定完成请求，用于发现异常、断流和答案落库失败                     | 正常收到 `DONE`、无 `ERROR` 且答案成功落库的请求数 ÷ 总请求数 | 代码自动计算                                                             |
| 路由准确率 `route_accuracy`           | 判断 Agent 能否正确选择直接回答或进入 RAG；路由错误会导致无依据回答或不必要的检索 | 实际路由与人工金标一致的案例数 ÷ 总案例数                     | 人工标注期望路由，代码比较                                               |
| 文档召回率 `document_recall@k`        | 判断回答问题所需的知识库文档是否被成功找到，是检索环节最核心的指标                | 实际召回的金标文档数 ÷ 金标文档总数                           | 人工标注相关文档 ID，代码计算                                            |
| 关键事实覆盖率 `required_fact_recall` | 判断答案是否包含用户需要的核心事实，反映答案的正确性和完整性                      | 答案覆盖的金标关键事实数 ÷ 金标关键事实总数                   | 初版关键词或规则匹配，后续升级为 LLM Judge                               |
| 答案忠实性 `groundedness`             | 判断答案中的事实是否都能被实际召回资料支持，用于发现幻觉和无依据补充              | 有资料支持的答案陈述数 ÷ 全部可验证陈述数                     | 初版人工抽评，后续使用经过校准的 LLM Judge                               |
| 无答案识别准确率 `no_answer_accuracy` | 判断知识库没有答案时，Agent 能否承认资料不足，而不是猜测或编造                    | 正确识别资料不足的案例数 ÷ 无答案案例数                       | 人工标注 `expected.noAnswer`，以固定表述规则初评；后续可替换为 LLM Judge |
| 首文本时延 `time_to_first_text_ms`    | 衡量用户多久看到第一段答案，是 SSE 流式接口最直观的体验指标                       | 第一个 `TEXT` 事件时间 − 请求开始时间                         | 自动采集，报告 p50、p95 和最大值                                         |
