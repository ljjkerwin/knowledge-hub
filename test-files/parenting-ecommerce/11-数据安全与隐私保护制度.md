# 萌宝优选数据安全与隐私保护制度

## 一、数据分类分级

### 1.1 数据分类

| 数据类别 | 示例 | 存储位置 |
|----------|------|----------|
| 用户个人信息 | 姓名、手机号、地址、宝宝信息 | PostgreSQL加密存储 |
| 交易数据 | 订单、支付、退款记录 | PostgreSQL |
| 商品数据 | 商品信息、价格、库存 | PostgreSQL + Redis |
| 内容数据 | 文章、评价、社区帖子 | MongoDB |
| 行为数据 | 浏览记录、搜索记录、点击行为 | Elasticsearch |
| 系统日志 | 操作日志、访问日志、错误日志 | ELK Stack |

### 1.2 数据分级

| 级别 | 定义 | 访问控制 | 加密要求 |
|------|------|----------|----------|
| L1公开 | 可对外公开的数据 | 无限制 | 无需加密 |
| L2内部 | 公司内部使用数据 | 员工账号认证 | 传输加密 |
| L3敏感 | 涉及用户隐私的数据 | 角色权限控制 | 存储+传输加密 |
| L4机密 | 核心商业秘密、密钥 | 最小权限原则 | 端到端加密 |

**用户个人信息属于L3敏感数据**，包括：
- 身份信息：姓名、身份证号、手机号
- 地址信息：收货地址、IP地址
- 宝宝信息：姓名、出生日期、性别
- 支付信息：银行卡号（脱敏存储）、支付账户

## 二、用户隐私保护

### 2.1 隐私政策要点

萌宝优选《隐私政策》的核心承诺：

1. **最小必要原则**：仅收集提供服务所必需的最少个人信息
2. **知情同意**：收集个人信息前明确告知用户并获得同意
3. **目的限制**：仅将个人信息用于收集时声明的目的
4. **安全保障**：采取合理安全措施保护个人信息
5. **用户权利**：用户可查询、更正、删除其个人信息
6. **第三方共享**：与第三方共享个人信息前获得用户明确同意

### 2.2 个人信息收集范围

| 功能场景 | 收集信息 | 是否必要 | 法律依据 |
|----------|----------|----------|----------|
| 注册账号 | 手机号、昵称 | 必要 | 合同履行 |
| 下单购买 | 收货人姓名、地址、手机号 | 必要 | 合同履行 |
| 支付 | 支付账户信息 | 必要 | 合同履行 |
| 宝宝档案 | 宝宝姓名、出生日期、性别 | 非必要 | 用户同意 |
| 个性化推荐 | 浏览、搜索、购买记录 | 非必要 | 用户同意 |
| 客服沟通 | 聊天记录、通话录音 | 必要 | 合同履行 |
| 活动参与 | 姓名、联系方式 | 视活动而定 | 用户同意 |

### 2.3 用户权利保障

用户可通过App"设置-隐私中心"或联系客服行使以下权利：

| 权利 | 说明 | 响应时限 |
|------|------|----------|
| 知情权 | 了解个人信息的收集和使用情况 | 即时（App内查看） |
| 查询权 | 查询已收集的个人信息 | 15个工作日 |
| 更正权 | 更正不准确的个人信息 | 15个工作日 |
| 删除权 | 请求删除个人信息 | 15个工作日 |
| 撤回同意 | 撤回对个人信息处理的同意 | 即时生效 |
| 注销账号 | 永久删除账号及关联数据 | 15个工作日处理，30天冷静期 |
| 数据导出 | 以可读格式导出个人信息 | 15个工作日 |

### 2.4 未成年人保护

- 14周岁以下未成年人属于敏感个人信息，收集需获得监护人同意
- 宝宝档案功能需绑定监护人账号
- 未经监护人同意，不得向14岁以下儿童推送商业广告
- 定期清理超过2年未活跃的未成年人数据

## 三、数据安全技术措施

### 3.1 数据加密

| 场景 | 加密方式 | 标准 |
|------|----------|------|
| 数据传输 | TLS 1.3 | 全站HTTPS |
| 数据库存储 | AES-256 | 敏感字段加密 |
| 密码存储 | bcrypt | 单向哈希+盐值 |
| 支付信息 | RSA-2048 | PCI DSS合规 |
| 文件存储 | 服务端加密（SSE） | RustFS加密 |

### 3.2 访问控制

**权限模型：RBAC（基于角色的访问控制）**

| 角色 | 数据访问范围 | 典型岗位 |
|------|-------------|----------|
| 超级管理员 | 全部数据 | CTO、安全负责人 |
| 运营管理员 | 业务数据（脱敏） | 运营总监、运营经理 |
| 客服人员 | 单个用户数据（按需） | 客服专员 |
| 数据分析师 | 聚合数据（脱敏） | 数据分析师 |
| 开发人员 | 测试环境数据 | 开发工程师 |
| 供应商 | 自身商品数据 | 供应商管理员 |

**访问控制规则：**
- 最小权限原则：仅授予完成工作所需的最低权限
- 权限审批流程：权限申请→直属上级审批→安全团队审核→开通
- 定期权限审计：每季度清理离职人员和过期权限
- 敏感操作二次验证：查看用户手机号、导出数据等需二次验证

### 3.3 数据脱敏

| 数据类型 | 脱敏规则 | 示例 |
|----------|----------|------|
| 手机号 | 保留前3后4 | 138****5678 |
| 身份证号 | 保留前4后4 | 3301**********5678 |
| 姓名 | 保留姓 | 张** |
| 银行卡号 | 保留后4尾 | ****5678 |
| 地址 | 保留省市 | 浙江省杭州市**** |
| 邮箱 | 保留首字母和域名 | z***@example.com |

## 四、数据安全事件响应

### 4.1 安全事件分级

| 级别 | 定义 | 响应时限 | 上报对象 |
|------|------|----------|----------|
| P0严重 | 大规模数据泄露（>10000条） | 15分钟 | CEO + 法务 + 安全团队 |
| P1高 | 数据泄露（1000-10000条） | 30分钟 | CTO + 安全团队 |
| P2中 | 数据泄露（<1000条）或未授权访问 | 2小时 | 安全负责人 |
| P3低 | 安全漏洞或异常行为 | 24小时 | 安全团队 |

### 4.2 应急响应流程

```
发现事件 → 初步评估（15分钟）→ 启动应急响应 → 控制影响范围 → 调查取证 → 修复漏洞 → 通知受影响用户 → 监管报告 → 复盘改进
```

**法律要求：**
- 根据《个人信息保护法》，发生个人信息泄露需在72小时内向监管部门报告
- 需及时通知受影响的用户，告知泄露的信息类型、可能影响和已采取的措施

### 4.3 数据备份与恢复

| 备份类型 | 频率 | 保留时间 | 存储位置 |
|----------|------|----------|----------|
| 全量备份 | 每日2:00 | 30天 | 异地机房 |
| 增量备份 | 每小时 | 7天 | 异地机房 |
| 实时同步 | 实时 | - | 灾备数据库 |

- RPO（恢复点目标）：≤1小时
- RTO（恢复时间目标）：≤4小时
- 每季度进行一次灾备演练

## 五、合规要求

### 5.1 适用法规

- 《中华人民共和国个人信息保护法》（PIPL）
- 《中华人民共和国数据安全法》
- 《中华人民共和国网络安全法》
- 《儿童个人信息网络保护规定》
- 《信息安全技术 个人信息安全规范》（GB/T 35273）

### 5.2 合规审计

- 每年进行一次个人信息保护合规审计
- 每年进行一次等级保护测评（三级等保）
- 定期进行渗透测试和安全扫描（每季度）
- 重大版本上线前进行安全评审

### 5.3 员工数据安全培训

- 新员工入职必须完成数据安全培训（2小时）
- 每年进行一次全员数据安全意识培训
- 每季度发送安全意识提醒邮件
- 针对开发人员的专项安全编码培训（每半年一次）
